# 360° Review — 2026-07-07

Reviewers: architecture, security, test-quality, DX (parallel, read-only).
Severity vocabulary: Critical / Major / Minor per `rules/quality-gates.md`.

## Critical

1. **Host RCE via LLM-proposed test code** — `runner/test_runner.py:171-237`, wired in `orchestrator.py:363-364`. CWE-94/95/829.
   `evidence.test` (string authored by an LLM reading an untrusted diff) is written to `review-tests/` and executed on the HOST (`pytest -q -x`, `npm test`, `go test`, `rspec`) with operator privileges. Only gates: `ast.parse` syntax check + symbol-relevance check, neither constrains behavior. Prompt injection in a reviewed diff → arbitrary code exec, e.g. exfiltration of `~/.config/*-api-key`. Corroborated independently by architecture reviewer. This is the one finding the local-single-user threat model does NOT downgrade: untrusted diffs are the tool's designed input.
   Fix: run proposed tests in an ephemeral `--network none` read-only container with cpu/mem/pid limits; never on the host.

2. **Secret-handling code has zero tests** — `orchestrator.py:56-76` (API-key redaction in `_classify_failure`) and `run_*` Docker argv invariants (`:ro` mounts, key via env-name only). A refactor dropping the redaction leaks reviewer keys to stderr with no test failing.
   Fix: tests asserting secret → `***` in output; key absent from argv, present in env; mounts end `:ro`.

## Major

3. **Repo-mode SonarQube scoping bug** — `orchestrator.py` (`pipeline_repo` forwards `diff_mode="staged"` default to `SQ.run_sonarqube`); a full-repo review silently scopes SonarQube to staged changes. Fix: pass `diff_mode=None` in repo mode. (Direct symptom of finding 4.)
4. **`pipeline()` / `pipeline_repo()` duplication** — the whole flow is duplicated (~170 lines each) and has already diverged (finding 3; also: repo mode ignores `args.prompt`, omits the preflight "no target" message). Same pattern in `validate_finding` vs `validate_finding_repo`. Fix: extract shared stages.
5. **`--repo PATH` scopes only the LLM pass** — Semgrep and SonarQube still scan `project_root`, ignoring the subpath. Fix: thread the path through, or document.
6. **Fail-open broad excepts** — `sonarqube_runner.py:405,476`: `except (RequestException, Exception)` returns `[]` on ANY bug; ground-truth findings vanish indistinguishably from "clean". Fix: catch specific exceptions, let the rest propagate.
7. **SSRF via LLM-supplied `cwe_url`** — `validator.py:144-149,282-283,352-353`. CWE-918. `requests.head(url, allow_redirects=True)` on an LLM-controlled URL, no allowlist → internal-network prober (`169.254.169.254`, `localhost:9000`). Fix: allowlist `cwe.mitre.org` or validate IDs against the cached MITRE list only.
8. **SonarQube: hardcoded admin password + 0.0.0.0 bind** — `sonarqube_runner.py:30,98`. CWE-798. `reviewpass!2026` in git; `-p 9000:9000` binds all interfaces; anyone reaching host:9000 is admin and can mint tokens. Fix: bind `127.0.0.1:9000:9000`; random per-install password in the cache dir.
9. **Reviewer containers: secrets + network + sandbox off** — `orchestrator.py:84-86,105-114,139-148`. CWE-668. Live Claude creds volume / API keys in env inside networked containers consuming untrusted diffs; Gemini runs `--sandbox false`. Fix: `--network none` or egress restricted to model API; keep sandbox on.
10. **"E2E" tests never call the pipeline** — `tests/e2e/test_orchestrator_e2e.py` re-implements the flow by hand; `pipeline()`, `pipeline_repo()`, `main()`, return codes (2/1/3), the `surviving` filter, and SonarQube cross-check inclusion are all untested. Fix: drive `O.pipeline(args)` on a temp git repo with reviewers/PF/SR/SQ monkeypatched.
11. **SonarQube runner I/O layer untested** — token/auth lifecycle (`_ensure_token`, password fallback), diff-scoping pure functions (`_changed_paths`, `_minimal_covering_dirs`, `_find_tsconfigs`), the scoped `run_scan` branch, and top-level `run_sonarqube` have no coverage; the scoping helpers are the easiest high-value units in the repo.
12. **README/SKILL.md doc drift** — README layout lists `runner/test-runner.sh`/`semgrep-runner.sh` (don't exist; `.py` now), omits `orchestrator.py`, sonarqube/preflight/repo_collector/merger/repo-review prompt, `uv` dependency, SonarQube images. SKILL.md steps 4-5 reference the same dead `.sh` names; "single message, three Bash calls" contradicts the thread-pool reality (risk: pushes the agent to hand-run docker); `--no-test-runner` missing from Options; no explicit run command (`./orchestrator.sh [options]`).

## Minor

13. `test_runner.py:176-177` — `cmd.append(f"-k {test_name}")` is one argv token; pytest `-k` filtering silently fails. Fix: `cmd += ["-k", test_name]`.
14. `merge/merger.py:203-209` — MODIFY verdicts: last reviewer wins, order-dependent; an injected round-2 verdict can downgrade a CRITICAL to INFO (finding suppression). Fix: MODIFY may only raise severity, or keep original visible.
15. `orchestrator.py:209,221-233` — greedy `_JSON_BARE_RE` grabs over-broad blobs; prefer `raw_decode` from first `{`.
16. `orchestrator.py:334,564` — `setdefault("id", ...)` keeps reviewer-supplied ids; collisions misattribute verdicts. Always overwrite with source-prefixed id.
17. `orchestrator.py:248-252` — `generate_diff` conflates git failure with empty diff.
18. `repo_collector.py` — each file read up to 4x per run; read once into a map.
19. `orchestrator.py:86,110,147` — full prompt as docker argv element; ARG_MAX risk on big chunks; pipe via stdin/file.
20. `sonarqube_runner.py:151-153` — token cached world-readable (~0644); chmod 0600 / dir 0700.
21. `sonarqube_runner.py:344` — scanner uses `--network host` with SONAR_TOKEN in env; use a bridge network shared only with the server.
22. `Makefile:4` — `.PHONY` declares `typecheck` with no recipe; `make typecheck` silently no-ops; `check` doesn't include it.
23. `tests/test_sonarqube_runner.py:305-311` — tautological assertion (`X in cmd or Y not in cmd` can never fail).
24. Coverage asymmetries: `extract_json` raw_decode branch, `deduplicate_findings` higher-first case, `_render_finding` evidence branches, `map_result` default-map branches.
25. SKILL.md `--prompt` doc omits `repo-review`; README prompts list omits `repo-review.md`.

## Explicitly checked and clean

- All subprocess calls use list-argv, no `shell=True`.
- `_classify_failure` redacts API keys from logged tails (but see finding 2: untested).
- All project mounts into containers are `:ro`.
- Pure data-transformation layer (validator, merger, test_runner classification, repo_collector, result mappers) is genuinely well tested.

## Recommended attack order

1. Sandbox the test runner (finding 1) — the only true Critical; blocks trusting the tool on any untrusted diff.
2. Secret-handling tests (2) — cheap, holds the line on existing good behavior.
3. De-duplicate the two pipelines (4), fixing 3 and 5 in the same pass, then real pipeline-level e2e tests (10) to lock it in.
4. SonarQube hardening batch (6, 8, 20, 21) + validator SSRF allowlist (7).
5. Doc sweep (12, 25) + Makefile typecheck (22) + the small correctness minors (13-19, 23, 24).
